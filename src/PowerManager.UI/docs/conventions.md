# UI 工程规范（UI Conventions）

本文档定义面向桌面 WebView2 轻应用的**通用、可复用 UI 工程规范（Rules）**，与系统/后端规范 [docs/conventions.md](../../../docs/conventions.md) 职责正交，并服务于远期抽离独立 UI 壳模板的演进目标（见 [docs/roadmap.md](../../../docs/roadmap.md) §六）。具体到 `PowerManager.UI` 的需求与设计见 [requirements.md](requirements.md) 与 [design.md](design.md)。

---

## 一、 谨慎硬编码原则（决策树边界）

UI 设计必须严格区分**“必须自适应的动态量”**与**“决策树末端不需要自适应的物理/认知锚点”**，只在后者处谨慎使用硬编码：

| 类别 | 是否允许硬编码 | 规范要求 |
|---|---|---|
| **窗口/容器的内容高度** | **禁止** | 必须由前端 DOM 固有高度（Intrinsic Sizing）驱动或在受限视口内自然流式排布，严禁宿主写死业务内容高度去猜 DOM |
| **容器内部剩余空间填充** | **禁止** | 严禁对高度不确定的卡片使用 `flex: 1; justify-content: space-between` 强行拉扯撕裂出大块死白 |
| **根字号与自由窗口高度耦合** | **禁止** | 严禁在自由窗口态用 `vh` 反推根字号同时又让窗口高度跟随内容变化，避免形成正反馈循环 |
| **业务参数边界与枚举** | **禁止散落** | 时长/阈值等业务上下限归属单一策略源，不在前端多处重复写死 |
| **Design Tokens（视觉公理）** | **允许且集中** | 色板、基准字号、圆角阶梯、间距阶梯、动效曲线集中定义在 `:root` 与主题块中，组件规则只消费语义 Token |
| **人机工效边界** | **允许且克制** | 仅在决策树末端保留必要边界常数：窗口最小可用尺寸、工作区最大占比安全上限（防遮挡任务栏）、响应式布局断点、单控件（如滑条）舒适最大宽度上限 |

## 二、 尺寸所有权与单向依赖

1. **自由窗口态（非最大化、用户未手动拖拽改高度）**：
   - 前端 DOM `<main>` 的固有内容高度是**唯一真相源**；
   - 前端通过 `ResizeObserver` 监听内容高度变化并异步上报宿主；
   - 宿主以垂直中心锚点对称贴合窗口客户区高度至 `Clamp(contentHeight, minHeight, workAreaMaxHeight)`，并确保窗口底边不越过任务栏；
   - 若用户手动拖拽改变了窗口高度或位置，宿主尊重用户选择（更新中心锚点或停止自动覆写高度）。
2. **受限视口态（最大化 / 用户手动锁定尺寸）**：
   - 宿主显式通知前端进入最大化态，由视口尺寸主导内容排布与比例缩放（无 `vh` 反馈环）；宽屏下通过横向重组降低纵向占用，极端矮屏通过媒体查询兜底。
3. **滚动退化边界**：
   - 仅当内容固有高度超过当前可用视口高度（如极端矮屏或最小窗口）时才允许垂直滚动；常规状态与常见屏幕分辨率下保持一屏完整可见；通过稳定滚动条槽位防止瞬态滚动条引发水平抖动。

## 三、 视觉焦点唯一与状态正交

1. **互斥选择组单一主焦点**：同一组互斥选项在任意时刻**至多只有一个**强视觉边框焦点。
2. **状态视觉编码正交**：
   - **已生效态**：实线主题边框 + 柔和主题底色；
   - **待确认草稿态**：虚线主题边框 + 状态徽标 + **中性底色**（同时撤下原生效项的强边框，避免双项同时高亮）；
   - **未选中态**：中性底色 + 细弱边界。
3. **辅助配置容器克制着色**：草稿编辑区的辅助容器使用中性槽位底色 + 细边框，不重复铺满主题色，避免整块区域“全局变色”。

---

## 四、 交互范式一致与安全放弃

1. **同类参数同形态**：凡连续区间参数，统一采用“滑动条 + 数值读数 + 快捷档位 chips”组合；交互控件（尤其是滑动条）须设合理最大宽度上限，不随宽屏无限拉长。
2. **显式提交与无副作用放弃**：涉及连续参数微调的操作统一采用“前端草稿编辑 → 显式确认提交”；拖动滑条仅更新本地草稿，不发 IPC；任何未确认的取消、离开或关窗操作都必须**严格维持后端原有真实状态**，绝不隐式切换状态。

---

## 五、 空间对称与响应式重组

1. **平级信息优先对称网格**：同层级信息项应采用对称列数与平级卡片结构（避免“若干单格 + 单个套娃跨列格”的不对称拼接），并随容器宽度在紧凑纵向排布与宽屏横向排布间平滑重组。
2. **展开附属面板不挤压主控件**：展开说明/规则类附属面板时，不得把主操作条塞进被压窄的侧栏导致按钮折行或另一侧出现大片留白。

---

## 六、 双门禁验收规范

任何涉及前端样式、布局或窗口尺寸逻辑的改动，提交前必须同时通过以下两类验收，缺一不可：
1. **结构量化校验**：通过无头浏览器（与 WebView2 同源 Blink 引擎）自动化校验全状态 × 多视口下的溢出情况与内容高度合理性；
2. **真实渲染目视检查**：对默认启动态、草稿态、已生效态与宽屏展开/最大化态截屏目视核验，确认无空白断层、无控件过长拉伸、无全局误高亮。
