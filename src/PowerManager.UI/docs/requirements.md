# 交互界面需求规格（UI Requirements）

本文档只定义 `PowerManager.UI` **必须表现出的外部交互行为与约束（What）**，不包含 CSS/WinForms 实现方案或历史修改过程。工程规范见 [conventions.md](conventions.md)，实现设计与追踪矩阵见 [design.md](design.md)。

---

## 一、 适用范围与非目标（Scope & Non-Goals）

- **目标形态**：Windows 11 桌面轻量交互窗口，提供模式切换、电池状态查看、单次临时冲高与规则查看的统一图形入口（承接顶层 `NFR-02`）。
- **明确不做（Non-Goals）**：
  - 不引入 Node/npm 前端构建链；
  - 不进行后台高频周期轮询（沿用顶层 `NFR-01` 事件驱动与按需刷新原则）；
  - 不提供永久修改日常充电上限（`75%–80%`）的开关或输入框；
  - 不直接修改系统电源设置或硬件 EC，所有控制均经由后端受控契约执行。

---

## 二、 外部可验收行为需求（`UI`）

| 编号 | 需求描述 | 验收标准 |
|---|---|---|
| **UI-01** | **单实例与系统主题同步** | 同一管道下仅允许一个窗口实例，重复启动时激活已有窗口；窗口标题栏与页面内容跟随 Windows 浅/深色模式自动切换且热更新 |
| **UI-02** | **自由窗口内容贴合与对称定位** | 非最大化且用户未手动拖高时，窗口高度随内容自动贴合（底部无大块死白，且不超过工作区安全上限）；内容展开再收起后窗口回到原垂直中心位置，点击交互不产生左右抖动 |
| **UI-03** | **最大化与宽屏自适应** | 窗口最大化或宽屏时自动识别窗口态，适度放大排版比例、横向重组控件并保持垂直居中与一屏完整可见（常见屏幕分辨率下零垂直滚动），且滑条等控件不无限拉长 |
| **UI-04** | **保持运行统一草稿确认与安全放弃** | 保持运行时长支持 `1–24` 小时连续调节（含滑条与快捷档位）及“直到手动改回”；点击进入或修改时长时先进入待确认草稿态，点击“确认”才生效；未确认就取消、切回或关窗时严格维持后端原有真实状态（普通维持普通，保持运行维持原倒计时） |
| **UI-05** | **互斥视觉焦点唯一** | 模式选择组在任意时刻至多只有一个强边框焦点；已生效态与待确认草稿态视觉明确区分（草稿态仅目标项虚线框 + 状态徽标，不全局变色） |
| **UI-06** | **规则面板按需展开且不挤压主控区** | 支持手动展开/收起规则与电源模式明细（宽屏自动展开），展开后左右高度平衡，不导致时长配置条折行或一侧出现大片留白 |
| **UI-07** | **电池状态对称展示与按需刷新** | 以平级对称网格展示 6 项核心指标（电池温度、整机功耗、充电电流、最热传感器、插电/电池电源模式），并支持按需刷新 EC 读数与临时冲高参数提交 |
| **UI-08** | **无宿主离线预览与快捷键** | 在无 WebView2 宿主时自动启用内置 Mock 桥接，支持浏览器直接预览全部业务态与主题；支持 `Esc` 关闭窗口、`F5` 刷新状态与一键打开数据目录 |
