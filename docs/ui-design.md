# 交互界面设计（UI Design）

本文档定义 `PowerManager.UI` 的**信息架构、窗口与响应式行为、异常态引导、交互状态机与验收方式**；外部行为需求见 [requirements.md](requirements.md)（`NFR-02`–`NFR-04`、`SLP-02`、`CHG-02`），进程边界与 JSON-RPC / IPC 契约见 [design.md](design.md) §四。

---

## 一、 设计原则与前端约束

1. **零构建链与离线预览（开发约束，非用户需求）**：前端由 `src/PowerManager.UI/web/` 下的 `index.html`、`styles.css`、`mock.js`、`app.js` 静态文件组成，编译时由 `EmbeddedWebAssets.cs` 内嵌进可执行文件；无 WebView2 宿主时自动启用 `mock.js` 离线桥接（其示例文案与 `UiStateFormatter` 保持一致），支持浏览器直接预览。
2. **字号与主题跟随系统**：页面保持固定基准字号，完全由 Windows DPI 缩放控制清晰度（不在最大化时用 `vh` 拉伸或压缩字体）；组件统一消费 `:root` 中的语义 Design Tokens，宿主同步 Windows 浅/深色标题栏与背景色。
3. **显式确认与安全放弃**：凡涉及连续参数微调的操作（保持运行时长、临时冲高），先在前端编辑草稿，仅在用户显式点击确认后发 IPC；未确认即取消、切回或关闭窗口严格维持后端原有状态。
4. **策略数字不在前端手写**：滑条范围、规则说明与提示文案中的策略数字（时长、阈值、温度、百分比）一律取自 `get_state` 下发的 `policy`（来源 [PowerPolicy.cs](../src/PowerManager.Core/Policy/PowerPolicy.cs)，见 `PolicySnapshot`）。措辞留在前端：`app.js` 用模板字符串拼句子，`index.html` 用 `<span data-policy="键名">` 占位，键名以 `_sec` 结尾的按时长格式化（`fmtDur`）。快捷档位属于界面设计，留在 `app.js`，超出 `policy` 范围的档位自动隐藏。`UiPolicyConsistencyTests` 会扫描 `index.html` 与 `app.js` 中手写的“数字 + 单位”，并校验 `mock.js` 的 `policy` 副本与 `PolicySnapshot` 一致。

## 二、 窗口行为与响应式规则

- **紧凑态与展开态**：
  - 紧凑逻辑宽度 `720px`，仅显示双列模式卡片；用户点击“规则与电源模式”展开面板时，窗口平滑动画至 `960px`（展开态左右分栏，左栏模式卡片、右栏规则说明与数据目录入口）。
  - 窗口宽度 `>= 880px`（含最大化）时规则面板常驻展开并**隐藏折叠按钮**，避免宽屏或最大化状态下出现“收起面板反把窗口缩回小窗”的冲突。
- **高度贴合与滚动退化**：
  - **自由窗口态**：前端通过 `ResizeObserver` 上报 `<main>` 固有内容高度，宿主按当前垂直中心锚点对称贴合窗口高度（上限工作区 `94%`）；若用户手动拖拽过窗口高度，则尊重用户尺寸不再覆写。
  - **最大化态**：内容区适度放宽并在视口内垂直居中；常规分辨率（如 `1440×912`、`1920×1040`）一屏完整可见，极端矮屏自然允许垂直滚动而不牺牲字体清晰度。

## 三、 信息架构与状态反馈

页面自上而下分为三块：**顶栏**、**模式卡片**、**电池与冲高卡片**。

1. **顶栏与常驻状态引导**：
   - 展示标题与常驻调度状态胶囊：运行中为绿点；离线时变为红点并直接提供“启动”入口（调用 `start_agent` 拉起计划任务）；`--dry-run` 模式下附加标识并隐藏生产启动入口。
2. **模式卡片**：
   - 模式选择项使用语义化按钮（支持 `Tab` 聚焦与 `Enter`/`Space` 触发），并保证互斥组任意时刻至多一个强边框焦点；
   - 保持运行时长条与主动睡眠告警条均位于底部通栏，不被展开的规则面板挤压；
   - **主动睡眠告警条**：当后端处于主动睡眠状态（`forced_sleep = true`）时高亮提示“2 分钟内未入睡将自动休眠，开盖活动可中止”。
3. **电池与冲高卡片**：
   - **电量与充电区间**：大字号百分比、实时充放电功率文案、区间进度条、EC 上次更新时间徽标（距今 `>= 30` 分钟标黄提醒，附事件驱动触发说明）与按需“刷新读数”按钮。
   - **语义分组指标区**：
     - **EC 硬件遥测（4 项）**：电池温度、整机功耗、充电电流、最热传感器（紧凑 `2×2` / 宽屏 `4×1`）；
     - **Windows 电源模式（2 项）**：插电电源模式、电池电源模式（`2×1` 独立一行，高亮当前供电方式），与 EC 读数明确区分语义与时效性。
   - **底部提示条**：热保护慢充时（`slow = true`）优先展示黄色慢充说明，否则展示上次冲高自动回落原因。
   - **临时冲高区**：未冲高时提供 3 组“滑条 + 读数 + 快捷档位”（宽屏同行排布且滑条有最大宽度上限）与“开始冲高”按钮；冲高中切换为紧凑进度条卡片。
4. **快捷键**：`Esc` 关闭窗口、`F5` 刷新状态，以及 Tab/Enter 键盘操作主控区。

## 四、 保持运行“草稿确认”状态机

保持运行时长支持 `1–24` 小时连续调节（快捷档位 `2 / 4 / 8 / 12 / 24` 小时）及“直到手动改回”（`hours = 0`，默认 `12` 小时）：

| 后端真实状态 | 用户操作 | 前端视觉状态 | 取消 / 关窗 | 点击“确认” |
|---|---|---|---|---|
| **普通模式** | 点击“保持运行” | 撤下“普通”高亮，仅“保持运行”显示虚线框 + `待确认` 徽标；底部条展示滑条、快捷档位、预计结束时刻与“取消/确认” | 放弃草稿，**维持普通模式**（零 IPC） | 提交 `set_mode('run', hours)`；成功切为实线已生效态，失败保留草稿并提示 |
| **保持运行（已生效）** | 拖动滑条或点其他档位 | 底部条保留当前倒计时并标注待确认变更，显示“取消/确认” | 放弃草稿并复位，**维持原倒计时** | 提交 `set_mode('run', hours)` 按新时长重设到期时间 |
| **保持运行（已生效）** | 点击“普通” | 立即提交 `set_mode('normal')` 切回普通模式并收起底部条 | — | — |

- **“直到手动改回”与滑条的联动**：选中“直到手动改回”时滑条置灰以示当前不按小时计时；再次点击或拖动滑条即自动切回滑条对应的定时小时数草稿。

## 五、 验收门禁

涉及前端样式、布局或窗口尺寸的改动，提交前须同时通过：
1. **自动化布局校验**：`python scripts/verify_ui_layout.py`（Edge 无头 Blink 引擎校验自由态固有高度与常规最大化视口零垂直溢出）；
2. **冒烟与目视检查**：`PowerManager.UI.exe --dry-run --smoke-test` 退出码 `0`，并目视核验默认态、草稿态、展开态与最大化态。
