# ADR-0004: 事件驱动调度，所有定时由单一 Waitable Timer 驱动

## 背景

驱动力：

- 常驻程序与硬件任务的唤醒和进程启动都消耗电量；目标 G2 要求放进包里时尽量不做无用功。
- 系统进入现代待机或休眠后，进程内的普通计时器停止走时，醒来后到期时刻不准。
- 需要定时的事情不少：合盖睡眠延迟、保持运行到期、冲高保持与兜底、通勤查温、主动睡眠检查。

## 决策

1. **常驻程序完全事件驱动**：阻塞等待 Win32 电源、合盖、屏幕、电量、锁屏通知与管道请求，不做固定周期轮询。
2. **单一 Waitable Timer**：所有未来时间点按墙上时间合并到一个定时器（不唤醒电脑）；醒来后按墙上时间重算剩余任务。
3. **硬件任务按事件运行**：只在开机、登录、唤醒（`Power-Troubleshooter` 1）、插拔电（`Kernel-Power` 105）以及常驻主动触发（电量每变 5%、冲高到点、通勤查温）时运行；多实例策略为 `Queue`，防止连续触发时丢失；WMI 调用在进程内通过 COM 发起。

## 备选方案

1. **定时轮询**（常驻每 30 秒查询状态，硬件任务每 5 分钟由计划任务拉起 PowerShell 执行 WMI 查询）：v1 采用过。硬件任务日均约 290 次，每次拉起 PowerShell 约 340 ms。事件驱动下为日均约 30 次；进程内 COM 读取 `BatteryStatus` 实测约 46 ms。
2. **进程内普通计时器**：系统冻结期间停止走时，醒来后无法及时补齐到期动作。

## 影响

- 常驻未运行或崩溃时，硬件任务的开机、唤醒、插拔电触发器仍独立维持日常阈值，Windows 自身的闲置超时仍提供基础睡眠保护。
- 常驻必须监听锁屏 / 解锁与活动显示器状态来配合事件流。
- 硬件无事件推送的指标（通勤期间的电池温度）只在对应状态下按需低频采样。
