# ADR-0001: 限定 Windows 11 与单一机型范围，仅保留上层可迁移边界

- **状态**：Accepted
- **日期**：2026-11-24

## 背景
项目当前服务于华为 MateBook 14 2024（`FLMH-XX`，Windows 11）。面对“是否扩展支持 Linux/macOS/鸿蒙”以及“是否提前为未来可能购买的其他品牌电脑编写通用多机型适配器”的问题，需要明确系统边界。

## 决策
1. **操作系统边界**：仅适配 Windows 11，不开发跨平台版本。
2. **硬件适配边界**：当前仅实现 MateBook 14 2024 这一套 EC/WMI 硬件适配器，不为未知机型提前编写多品牌兼容或降级框架。
3. **代码隔离边界**：将硬件读写收拢在极简接口之后，使基于标准 Win32/WinRT API 的上层调度逻辑（状态机、事件监听、闹钟、通知、UI）保持可跨 Windows 机器迁移的能力。

## 依据
1. **跨平台收益极低**：macOS 由系统闭环管理电源与休眠；Linux 可通过 `sysfs`（如内核自带 `huawei-wmi`）与 `systemd-logind`/`tlp` 原生配置完成调度，无需从零维护常驻消息循环；鸿蒙 PC 未向第三方应用开放底层 EC 写入与睡眠劫持权限。
2. **多品牌 EC 无法提前验证**：各厂商对充电阈值和温度读取的 WMI 方法、指令字节或内核驱动完全碎片化。在没有目标真机与固件样本的前提下，提前编写的多品牌适配代码无法实测，只会成为死代码。
3. **固件行为不可预测**：当前部分调度策略源于本机实测特性（如无 S3 睡眠、轻触电源键被固件过滤）。未来新设备可能原生支持 S3 或在 BIOS 内置充电上限，届时无需其中部分兜底逻辑。
4. **上层天然可复用**：模式切换、Win32 消息监听、电源模式设置与 Toast 通知均依赖标准 Windows API，只要与硬件接口解耦，未来换用其他 Windows 设备时仅需按需重写硬件适配器即可沿用上层逻辑。

## 影响
- 避免当下引入无用抽象与复杂的多机型降级逻辑，聚焦当前设备稳定性。
- 硬件读写收拢在 `PowerManager.Hardware.MateBook` 一个项目内（只有 `PowerManager.BatteryCharge` 引用它），并要求改动硬件与系统接口前先用独立脚本实机验证（见 [ARCHITECTURE.md](../../ARCHITECTURE.md) §5）。
