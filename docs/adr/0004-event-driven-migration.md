# ADR-0004: 从定时轮询全面迁移至事件驱动与一次性 Waitable Timer

- **状态**：Accepted
- **日期**：2026-11-22

## 背景
早期实现中，`power-mode/` 每 30 秒轮询一次系统状态，`battery-charge` 每 5 分钟通过计划任务拉起一次 PowerShell 执行 WMI 查询（日均约 290 次，单次起 PowerShell 约 340 ms），存在无效唤醒与进程启动开销。

## 决策
1. **常驻进程（`agent`）完全事件驱动**：阻塞等待 Win32 电源/合盖/屏幕/电量/锁屏解锁通知与 UI 请求，**取消任何固定周期轮询**。
2. **单一 Waitable Timer 负责所有未来时间点**：将合盖 1 分钟、保持运行到期、冲高到期/保持满、通勤每 3 分钟查温度、兜底检查统一收拢至一个按墙上时间计算的等待式定时器（不唤醒电脑），醒来后按墙上时间重算剩余任务。
3. **EC 任务去定时化与直接 COM 调用**：取消每 5 分钟的计划任务定时触发，改为仅在开机、登录、唤醒（`Power-Troubleshooter 1`）、插拔电（`Kernel-Power 105`）以及常驻主动唤醒（电量每变 5%、冲高到点、通勤查温度）时运行，任务多实例策略设为 `Queue` 以防连发丢失；WMI 调用改由进程内 COM 库直接发起（不再拉起 PowerShell）。

## 依据
1. **减少无意义进程开销与唤醒**：改为事件驱动后，EC 提权任务运行频率从约 290 次/天降至约 30 次/天；进程内直接调 COM 读取标准 `BatteryStatus` 实测约 46 ms（相比拉起 PowerShell 约 340 ms 显著降低）。
2. **系统休眠对定时器的影响**：系统进入现代待机或休眠冻结后，常规进程内计时器会暂停走时；使用基于墙上时间的 Waitable Timer 可在唤醒瞬间立即校准并补齐到期动作。

## 影响
- 即使常驻进程未运行或崩溃，EC 任务的开机/唤醒/插拔电触发器仍能独立兜底维持 75%–80% 阈值，Windows 自身闲置超时也能维持基础睡眠保护。
- 常驻必须监听锁屏/解锁及活动显示器状态以配合事件流，相关 Windows 行为边界见 [windows-standby-and-toast.md](../reference/windows-standby-and-toast.md)。
