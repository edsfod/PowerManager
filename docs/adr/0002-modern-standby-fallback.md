# ADR-0002: 现代待机下禁用电源键，采用“缩短闲置超时 + 休眠兜底”实现睡眠控制

- **状态**：Accepted
- **日期**：2026-11-22
- **参考依据**：[windows-standby-and-toast.md](../reference/windows-standby-and-toast.md)

## 背景
在“跑实验时关屏/合盖不断网不断任务，但普通模式下合盖 1 分钟后睡眠，且能防止在包里意外唤醒发热”的需求下，需要确定如何通过程序可靠控制电源键、合盖与睡眠状态。

## 决策
1. **禁用电源键**：将 Windows 电源键动作设为“不采取任何操作”，关屏仅依赖闲置超时，关机与手动睡眠通过开始菜单触发。
2. **合盖动作交由常驻接管**：Windows 合盖动作统一设为“不采取任何操作”。普通模式下合盖 1 分钟后（且无外接活动显示器时），由常驻程序临时将关屏与睡眠超时缩短至数秒以触发系统睡眠；开盖或唤醒后恢复原超时。
3. **休眠兜底（S4）**：在常驻主动触发睡眠后 2 分钟若系统仍未进入睡眠阶段（或合盖状态下意外唤醒后 2 分钟仍未睡下且非“保持运行 + 插电”），调用 `SetSuspendState(Hibernate)` 强制休眠。

## 依据
1. **电源键与关屏耦合**：实测本机轻触电源键被固件过滤，设为“关闭显示器”并按住 1–2 秒会直接进入现代待机并冻结后台，无法实现“按电源键只关屏不中断后台”。
2. **本机无 S3 睡眠，API 无法强制进入现代待机**：实测调用 `SetSuspendState(睡眠)` 与 `NtInitiatePowerAction(睡眠)` 在有 CPU 负载时均直接转为 S4 休眠，模拟睡眠键无反应；程序可控进现代待机的唯一途径是临时缩短闲置超时（且仅在屏幕先关闭、整机空闲时生效）。
3. **高负载下的防过热底线**：当后台正在跑实验时，缩短闲置超时无法让系统进入现代待机；此时若在包里通勤超过 30 分钟或电池温度达到 40 °C，必须依赖休眠兜底以防止持续高功耗发热。

## 影响
- 普通模式下若后台确实在运行高负载任务，合盖 1 分钟后因睡不下去会在第 3 分钟转为休眠（由休眠文件承担约 12.6 GB 写入，但仅在兜底时发生）。
- 因为合盖动作设为“不采取任何操作”，合盖后系统不再发送“显示器已关闭”通知，外接显示器检测必须改用 Win32 `QueryDisplayConfig`。
