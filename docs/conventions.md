# 工程与编码规范（Conventions）

本规范服务于当前项目边界（仅面向 Windows 11；上层调度保持可跨机器迁移能力，当前仅实现 MateBook 14 2024 硬件适配器），用于约束模块内聚性、配置解耦与接口可验证性。

---

## 一、 高内聚与边界隔离

1. **依赖单向流动**：
   - 上层调度（模式状态机、闹钟、通知、UI）严禁直接引用厂商专有 WMI 指令字节（如 `03 10`）、EC 寄存器地址（如 `0x0268`）或具体机型的固件假设。
   - 所有底层硬件访问必须收拢在单一硬件适配模块内，对外仅提供语义化接口（例如读写充电阈值、读取电池温度）。
2. **禁止隐式状态耦合**：
   - 跨进程/跨任务通信必须通过显式、结构化的通信契约（如定义清晰的 IPC 协议或状态文件 Schema），不得依赖未文档化的全局副作用。

---

## 二、 消除硬编码与配置分离

1. **策略参数与业务逻辑分离**：
   - 用户策略常量（如日常基准阈值 `75–80%`、电池温度上限 `40 °C`、各模式闲置关屏/睡眠超时、保持运行可选时长）必须集中定义在代码内单一只读策略表或结构化配置中，禁止散落硬编码在 `if/else` 业务分支内。其中受防遗忘约束保护的日常基准阈值 `75–80%`（见 [ADR-0003](adr/0003-rejection-of-adaptive-charge.md)）仅集中定义于代码内常量表，不暴露外部可编辑配置文件或界面修改入口。
2. **硬件/平台常量归属底层**：
   - WMI 命名空间、方法名、指令字节、Event ID（`506/507/42/1`）及 `Reason` 映射表归属硬件或平台适配层，且必须能追溯至 [docs/reference/](reference/) 中的对应参考文档。
3. **路径与环境解耦**：
   - 禁止在逻辑代码中写死绝对用户目录路径（如 `C:\Users\...`）；可执行路径、注册表项与计划任务目标均由安装/部署入口统一解析并注册。

---

## 三、 接口验证与测试要求

1. **底层硬件与固件边界必须配备独立验证脚本**：
   - 凡涉及底层硬件（WMI/EC）或操作系统电源/固件行为边界（S0/S3 睡眠支持、电源键/合盖行为）的接口，**必须**在 `scripts/` 下提供不依赖业务主程序的独立验证脚本（例如 [verify_wmi_readonly.py](../scripts/verify_wmi_readonly.py)、[verify_power_boundaries.py](../scripts/verify_power_boundaries.py)）；上层 Win32/WinRT API（如 Toast 通知）随目标 C# 工程验证即可。
   - 未来接入新机型适配器或修改底层硬件/固件调用前，必须先通过对应接口验证脚本确认实机行为，再接入主程序。
2. **纯函数与副作用隔离**：
   - 状态转移、闹钟时刻计算、日志摘要拼装、冲高回落判定等核心逻辑必须编写为无系统 IO 副作用的纯函数，并配套单元测试；跑单元测试不得依赖真机 EC 或管理员权限。
3. **修改系统配置必须可回滚**：
   - 凡修改 Windows 电源方案、超时时间或按键动作的操作，必须在首次修改前保存原值快照，并仅在**用户主动停用**时提供完整的状态恢复路径（常驻程序异常退出后由计划任务重启期间应维持已写入策略作为兜底，不作回滚；EC 阈值因重启会复位为 `95–100%` 且以锁定 `75–80%` 为目标，不执行异常回滚；独立测试脚本若临时修改设置，须使用 `try...finally` 保证退出即恢复）。

---

## 四、 命名、日志、时间与仓库卫生

1. **命名规范**：
   - 目录名与文件名一律使用英文；文档正文与代码注释可使用中文。
2. **时间基准统一**：
   - 程序运行日志、状态时间戳统一使用 **UTC**（ISO 8601）；
   - 面向用户的 Toast 通知与界面展示使用**本机时间**；文档中涉及具体时刻时使用本机时间并注明时区（如 UTC+8）。
3. **运行时数据隔离**：
   - 运行时状态（`.json`）与日志（`.log`）集中存放在独立的运行时目录（如 `var/`），严禁提交进 Git 仓库。

| `docs/adr/` | 架构决策的背景、取舍依据与影响（Why） | 完整使用手册或逐行接口字典 |
